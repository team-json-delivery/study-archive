# 13 인간과 에이전트의 협업
- 불투명한 어시스턴트를 신뢰할 수 있는 팀 동료로 바꾸는 방법을 다룸
  - 효과적인 현업은 자율성을 얼마나 잘 조정하느냐에 달림 -> 전진적 위임과 실수 복구 방법 다룸

# 13.1 역할과 자율성
- 에이전트가 자율적 운영 단계로 어떻게 이동하고, 그에 맞춰 인간의 역할이 어떻게 변하는지 확인
  - 자율성이 커질수록 인간이 어떤 역할을 맡아야 하는가를 잊지 않아야 함 -> 답은 정해져 있지 않음

##### 13.1.1 에이전트 시스템에서 인간의 역할
- 에이전트 시스템의 규모가 커지고 성숙해질수록, 인간 협력자의 역할도 크게 변화
  - `실행자 -> 리뷰어 -> 협력자 -> 거버너`라는 네가지 역할로 이어지는 진전
    - 초기에는 사람은 주로 실행자, 에이전트 작업을 수동으로 실행하고 결과를 면밀히 감독
    - 초기 후, 고위험 혹은 규제가 엄격한 도메인에서 중요한 지점의 결정을 감독하는 리뷰어쪽으로 이동
    - 성숙한 워크플로에서는 사람은 협력자
      - 컨텍스트를 공유하고, 에이전트와 실시간으로 함께 결과물을 다듬
      - 사람은 고수준 목표를 설정하고 미묘한 판단, 예외 처리, 윤리적 판단이 필요할 때 개입
    - 가장 고도화된 도입 단계에서는 거버너로 전환
      - 정책 경계를 정의
      - 시스템 차원의 행동을 감사
      - 에이저트 시스템에 팀과 기능을 넘나들며 어떻게 상호작용하는지 감독

| 역할  | 인간의 일                    | 에이전트 자율성                  | 필요 인터페이스                   |
|-----|--------------------------|---------------------------|----------------------------|
| 실행자 | 작업 업로드, 모든 출력 검토         | 최소(항상 감독 필요)              | 단계별 안내, 촘촘한 피드백 루프         |
| 리뷰어 | 핵심 출렴만 샘플 검토             | 중간 수준(일상 업무 처리)           | 대시보드, 예외 플래그, 신뢰도 점수       |
| 협력자 | 우선 순위 조정, 공동 주석 작성       | 높음(초안 작성 및 실행, 사람의 감시 필요) | 공동 계획 UI, 컨텍스트 기반 주석 기능    |
| 거버너 | 정책 수립, 의사결정 감사, 사례 전달 감독 | 거버넌스 규칙 내에서의 자율성          | 정책 설정 화면, 감사 로그, 설명 가능성 도구 |

- 각 단계는 서로 다른 인터페이스 패턴과 의사 결정 도구를 요구
  - 실행자: 명확한 지시와 촘촘한 피드백 루프 필요
  - 리뷰어: 예외 관리와 감사 가시성을 위한 대시보드 필요
  - 협력자: 공동 작업 계획과 컨텍스트 기반 주석을 위한 인터페이스 필요
  - 거버너: 시스템 전반 관측 가능성, 정책 구성, 전달 로그, 규제 프레임워크와 인간 정렬 여부 검증 도구 필요

##### 13.1.2 이해관계자 정렬과 도입 추진
- 아무리 뛰어난 에이전틱 시스템이라도, 시스템 지원하도록 설계된 사람과 팀이 받아들이지 않으면 실패
  - 에이전트 도입을 단순한 소프트웨어 배포가 아닌 사람 중심의 변화 관리 과제로 다루어야함
- 성공적인 도입은 명확한 이해관계자 정렬에서 시작
  - 팀마다 기대하는 것을 초기에 드러내고 조율이 필요
- 첫 단계는 설계 초기부터 이해관계자를 참여시키는 것
  - 테스터가 아닌 공동 설계자로 참여
- 성공적 지표는 이해 관계자의 동의와 지지 필요
  - 작업이 빠르게 끝내더라도 신뢰를 떨어뜨리거나 마찰을 늘리는 에이전트는 사용되지 않음
- 에이전트 시스템 도입은 조직 전체가 학습할 수 있는 좋은 기회
  - 사용자와 개발자, 혹은 에이전트가 실제로 할 수 있는 일과 기대하는 일 사이 간극 확인 가능
  - 이러한 요구사항을 다듬으며 역할을 재조정하는 계기로 삼을 수 있음
- 지속적 도입과 활용을 위해 조직은 교육, 피드백 루프, 신속한 지원에 투자 필요
- 도입은 켜고 끄는 스위치가 아니라, 사람과 에이전트 동료가 함께 진화해 가는 여정

# 13.2 협업 확장
- 에이전트가 개인 어시스턴트에서 팀과 엔터프라이즈 차원의 협업자로 확장하는 방식과 시스템 설계에 요구하는 사항을 살펴봄
  - 개인 에이전트
    - 일정 관리, 이메일 요약 등과 같은 업무 담당
    - 권한은 제한적이고 위험도가 낮음
  - 팀 에이전트
    - 공유 지식 관리, 프로젝트 추적, 회의 요약등과 같은 업무 담당
    - 정교한 컨텍스트 관리 필요, 역할 기반 접근 제어(RBAC)가 핵심
  - 엔터프라이즈 전반 에이전트
    - 부서 간 워크플로 조정, 기능 간 데이터 통합/요약, 전략적 의사결정 등과 같은 업무 담당
    - 엄격한 정책과 정기적인 감사 필요
- 협업 인터페이스는 사람이 에이전트의 출력을 쉽게 검토하고 승인하거나 수정할 수 있게 해야함

##### 13.2.1 에이전트 범위와 조직 역할
- 모든 에이전트가 동일한 대상을 섬기도록 만들어 지지 않음
  - 활용 범위를 키워 갈수록 서로 다른 추상화 수준과 권한 수준에서 작동하는 에이전트를 채택하게 됨 -> 범위를 이해하고 의도적으로 설계 반영 필요
  - 접근 범위, 의사결정 자율성, 이해 관계자에 미치는 영향이 함께 변경 됨 -> 권한 부여, 감독, 컨텍스트 관리에 대해 맞춤형 설계 선택 필요
- 접근 제어 필요성
  - 가장 먼저이자 중요한 시사점
  - 에이전트 범위가 확장될수록 책임과 데이터의 민감도에 맞게 엄격한 역할 기반 접근 제어(RBAC)에 따라야함
- 에이전트 범위를 정의하는 일은 거버넌스 결정
  - 에이전트가 무엇을 할수 있고, 무엇을 해야하는지, 누구 감독 아래 작동해야하는 지 규정 필요

##### 13.2.2 공유 메모리와 컨텍스트 경계
- 에이전트 지원 수준이 확장되면 메모리를 어떻게 관리할지가 핵심 설계 이슈
  - 명확한 정책 없이 에이전트가 개인 혹은 민감 데이터에 접근할 수 있으면 안됨
- 메모리에 적절한 범위 설정 필요
  - 개인 에이전트는 고립된 메모리 사용
  - 팀과 부서 에이전트는 공유되지만 접근 제어되는 메모리 사용
  - 조직 전체 에이전트는 보존 규칙, 로깅, 감사 가능성을 강제하는 정책 기반 시스템 안에서만 작동 필요
- 메모리 투명하게 만드는 것은 중요
  - 사용자는 에이전트가 무엇을 기억하는지 알고 이를 제어할 수 있어야함 -> 인터페이스에 메모리를 눈에 보이게 드러내고, 메모리를 끌 수 있는 기능 제공
- 메모리는 단순 기술 기능이 아니라 권한, 신뢰, 위험의 원천

# 13.3 신뢰, 거버넌스, 컴플라이언스
- 자율성이 커지는 과정에서 신뢰, 책임성, 감독을 어떻게 구축하고 유지할지 고민
  - 협업이 안전하고 정렬된 상태를 유지하도록 하는 것이 목표
  - 에이전트는 투명하게 행동하고, 경계를 존중하며, 정의된 거버넌스 프레임워크 안에서 작동되어야 함
##### 13.3.1 신뢰의 라이프사이클
- 신뢰는 진화하는 개념
  - 일관된 성과, 투명한 행도으 명확한 경계를 통해 서서히 쌓임 -> 선을 넘거나 예측 불가능한 행동은 신뢰를 빠르게 무너질 수 있음
- 투명성은 신뢰 수준을 조정하는 데 핵심적인 역할
  - 자신의 신뢰도, 의사결정 요인, 불확실성이 개입되었는지 여부를 선제적으로 드러내야함 -> 인터페이스를 통해 명확히 드러내야함
- 점진적 위임
  - 라이프사이클 초기에는 검토나 승인은 사람에 맡겨야함 -> 시간이 지나 신뢰가 쌓이면 조금씩 자율성이 커질수 있음
  - 신뢰가 성장할 수 있도록 시스템을 설계하는 것이 안전하고 확장 가능한 도입에 필수
- 신뢰를 회복하는 메커니즘도 필요
  - 실수했을 때나 기대치가 바뀌었을 때, 행동 초기화나 재훈련 및 기능 제한을 할 수 있는 방법이 준비되어 있어야함
- 궁극적으로 에이전트에 대한 신뢰는 사람의 신뢰와 유사함
  - 에이전트를 통합하려는 시스템은 신뢰를 라이프사이클 전체의 설계 대상으로 생각해야함
##### 13.3.2 책임성 프레임워크
- 책임성은 윤리적 에이전트 설계를 위해 필수
  - 에이전트의 행동, 의사결정, 그 결과에 대한 명확한 책임라인이 존재하도록 보장
  - 책임성이 부재하면, 기술적,윤리적,운영적 실패가 방치되고 신뢰가 무너짐
  - 책임성을 수립하려면 감독 정책, 문의 전달 경로 같은 구조적 조치와 로깅, 윤리 감사 같은 기술적 조치가 모두 필요
- 책임성을 구체적으로 만들기 위해 이미 확립된 프레임워크를 도입하거나 변형해 사용 가능
  - AI RMF
  - 공동 설계 AI 영향 평가 템플릿
- 감사는 에이전트 행동, 시스템 출력, 의사결정 경로를 구조적으로 평가함으로써 책임성 유지에 핵심적인 역할
- 윤리 감사는 윤리적 위험, 의도치 않은 결과, 잠재적 피해를 식별하기 위한 구조화된 평가
  - 공정성은 1급 목적으로 다뤄져야함
- 행동 평가는 엣지 케이스나 애매한 입력 아래에서 에이전트의 수행을 관찰하여 감사를 보완함
  - 특정 프롬프트에 예측 불가능하게 반응 하는 등 의도치 않은 행동 발견 가능
- 윤리 감사와 행동 평가는 지속적이고 반복적인 프로세스여야함 -> 정기적 재평가 필요
- 효과적인 책임성은 의사결정, 행동, 컨텍스트 기반 추론을 상세히 포착하는 포괄적인 로깅과 추적성 시스템에 의존함
  - 추적성은 로깅을 한 단계 더 확장해 특정 사항에서 에이전트 행동을 재구성 가능하게 함 -> 전문 도메인에 특히 중요함
  - 로그는 안전하게 보호되고 책임감 있게 관리되어야 함
##### 13.3.3 대응 절차 설계와 감독
- 책임성은 로깅과 감사 뿐 아니라, 명확한 대응 절차 메커니즘과 인간 감독 구조가 뒷받침 되어야함
- 대응 절차 설계는 고위험이나 모호한 상황에서 에이전트가 권한을 넘어 행동하지 못하게 하는 정책 및 인프라 레이어
  - 인간 개입이 필요한 명확한 임계값을 정의
    - 의사 결정 유형, 위험 수준, 신뢰도 범위
- 대응 절차 경로는 기술 시스템과 조직 역할 양족에 모두 인코딩 되어있어야함
  - 에이전트는 언제 대응 절차를 시작해야 하는지 인식하고 작업을 적절히 라우팅해야함 
- 감독은 단지 사후 대응에 그치지 않음
  - 에이전트 행동을 선제적으로 모니터링하고 로그를 검토하며, 시간이 지나면서 대응 절차 정책을 다듬음
- 대응 절차 설계는 신뢰 수준 조정에도 핵심적인 역할을 함
  - 에이전트가 적잘한 순간에 사람에게 권한을 넘기며 안심하고 활용할 수 있음
- 대응 절차 설계는 피드백 루프를 지원해야함
  - 향후 에이전트 행동을 개선하는데 활용
##### 13.3.4 프라이버시와 규제 컴플라이언스
- 에이전트 시스템이 활용됨에 따라 점점 더 법적, 규제적 검토 대상이 되고 있음
  - 윤리적으로 투명하게 배포되도록 AI 전용 규제가 도입되고 있음
- 컴플라이언스를 지속 가능하게 만드려면 개발 파이프라인에 직접 통합해야함 
- 규제는 매우 빠르게 변화되고 있기에, 법률 모니터링, 아키텍처 유연성 등에 지속적인 투자가 필요
- 보안은 프라이버시를 보완함
  - 에이전트가 접근할 수 있는 데이터라도 침해, 유출, 변조로부터 보호되어야함
